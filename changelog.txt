*** TCGiant Sync Changelog ***

2026-08-12 - version 3.7.2
== Auto-Relist ==
- FIX: Auto-relisting a listing that has variations would have relisted it empty. eBay relists such a listing through a different call from an ordinary one, and the plugin used the ordinary one — which eBay accepts, recreating the listing and silently discarding every variation. The result would be a live listing with nothing in it to buy, reported in the log as a success.
- This is the same fault fixed for pushing in 3.7.1, in the one remaining place it still applied. Only stores with "Auto-relist ended listings" switched on and variable products were exposed to it.
- FIX: Auto-relist also skipped its own stock check on variable products. A variable product does not usually track stock itself — its variations do — so the check passed products with nothing left to sell, and eBay refused the relist. Sold-out variable products are now left alone as intended.

2026-08-12 - version 3.7.1
== Variable Products ==
- FIX: "Overwrite Price" was ignored for variations. The setting has always been respected for ordinary products, but variation prices were written from eBay on every sync whatever it said — so a seller who priced their variations differently in WooCommerce watched that work undone hourly, and turning the setting off changed nothing because it was never consulted. Variations now follow the same rule as everything else. A variation being created for the first time still takes eBay's price, since there is nothing to preserve.
- FIX: Changes to variations were never reaching eBay. eBay handles listings with variations through a different call from ordinary ones, and the plugin was using the ordinary one. eBay does not refuse this — it accepts the request, applies everything else, and quietly discards the variations. So the price went up and new variations never appeared, with nothing in the log to say why. Listings with variations, and fixed-price listings generally, now go through the call eBay intends for them.
- Push your variable products again to send the variations that were dropped. Nothing needs re-importing.
- Also fixed: new listings were being sent with their duplicate-protection reference twice over, which defeated the point of having one.

2026-08-12 - version 3.7.0
== Connecting to eBay ==
- Your eBay tokens no longer travel through the browser. Connecting used to finish by sending them back in the web address, which meant they were written into your browser history and your own server access logs, where they stay. An eBay refresh token remains valid for months, so that is a long time to leave one lying about.
- The connection now finishes with a single-use collection slip instead. Your site exchanges it for the tokens over a direct request that no browser sees. The slip expires after fifteen minutes, only answers to the site it was issued for, and is used up the first time it is presented, whether or not the request was entitled to it.
- Nothing about your eBay application changes: same keys, same registered address, same sign-in screen. This is only the last step, between our connection service and your site.
- Existing connections keep working and do not need redoing. The change applies the next time you connect or reconnect.

== Syncing ==
- Catching up on a backlog is now reliable regardless of the order eBay answers in. Work is resumed by position in the list of changes, and eBay does not promise to return that list the same way twice, so the same window queried again could have skipped or repeated items. The order is now fixed before any of it is processed.

2026-08-12 - version 3.6.2
== Syncing ==
- FIX: Syncing could stop completely and stay stopped, which is the real reason new listings were not arriving on some stores. When eBay reports a large number of changes at once, the plugin worked through every one of them in a single request, fetching each item individually. That request runs out of time part way through, so the sync never reaches its own finish, never records how far it got, and never clears the "in progress" marker.
- From then on every scheduled sync was turned away by that marker, hour after hour, and the position it reads from never moved. One store was stuck six days behind and falling further.
- Changes are now worked through in batches of 40, picking up where the last batch finished, so a busy period is caught up over several runs instead of failing on every attempt. The position only moves once the whole window is done, so an interruption costs a repeat rather than a gap.
- A sync that shows no progress for 30 minutes is now presumed to have failed and is replaced by a fresh one. The file lock has always released itself this way; the "in progress" marker did not, and had become the thing blocking everything.
- After updating, syncing resumes by itself. Anything missed while it was stuck is collected as it catches up; run Fetch Inventory if you would rather not wait.

== Connection ==
- FIX: "No valid eBay token" errors that came and went for no apparent reason. The connection service was occasionally returning a server warning ahead of its reply, which left the reply unreadable, so a perfectly good token was discarded and the site reported itself disconnected until the next attempt happened to succeed. The token is now recovered from replies like that, and the warning is recorded so the cause can be dealt with.

== Products ==
- FIX: Listings whose barcode field contains a stand-in such as "N/A" or "None" were all being given that as their SKU, so they collided with each other and had the eBay item number appended to tell them apart. Those values are now treated as no barcode at all, and the item number is used on its own.

== Logs ==
- Log times are now shown in your own timezone, wherever you are, while the log itself continues to be written in the site timezone. Hover over any time to see what the file recorded.

2026-08-12 - version 3.6.1
== New Listings ==
- FIX: A second cause of new eBay listings never appearing in WooCommerce, separate from the one fixed in 3.6.0 and affecting stores that do not filter by category at all.
- When a new listing arrived carrying the same SKU as an existing product, the plugin assumed the seller had relisted the same item under a new number, and moved the existing product across to the new listing. If that was not what happened, the new listing was swallowed by an unrelated product instead of becoming one of its own — so the new stock never appeared — and the product it took over was detached from the listing it was actually selling, then overwritten with the newcomer's title, price and images. Both happened silently.
- This is easy to hit when "eBay SKU Maps To" is set to Bin Location, because the WooCommerce SKU then falls back to the UPC or EAN, and a manufacturer barcode is not unique to one listing.
- The plugin now checks with eBay whether the older listing has actually finished before moving anything. If it is still live, the new listing is imported as its own product with a unique SKU, and the existing product is left attached to its own listing. If eBay cannot be reached, nothing is moved.
- The check only happens when two listings really do share a SKU, and only once per collision.

2026-08-12 - version 3.6.0
== New Listings ==
- FIX: New eBay listings were not appearing in WooCommerce. When you filter imports by category, each item is checked against your chosen categories before being imported. The hourly sync asks eBay only for what has changed, and eBay often answers with a partial record that leaves the category out entirely — so those items failed the check and were quietly dropped, before the follow-up request that would have identified them. Newly listed items were the worst affected, because they arrive through that route almost every time.
- The item is now looked up in full before being judged, and only when its categories really are missing, so there is no extra cost for items that arrive complete. If eBay cannot be reached at that moment the item is imported rather than dropped: a product that should have been filtered out is visible and can be removed, one that was wrongly dropped is invisible and never comes back.
- If listings are missing, run Fetch Inventory once to collect them.

== Variable Products ==
- FIX: Variations duplicated every time a variable product synced, which was most obvious when one sold. Variations were recognised only by their eBay SKU, and eBay leaves that field blank on most variations. With nothing to recognise them by, every sync built a fresh set and retired the previous set, so the product accumulated hidden copies carrying the same attributes and prices while the stock moved to the newest ones. The log line "Variation #... is no longer on eBay" appearing for variations that plainly were still on eBay was this happening.
- Variations are now recognised by their combination of options, which is what actually identifies them within a listing. Existing variations are reused, and one genuinely removed from eBay is still retired as before.
- Hidden duplicates already created are not removed automatically, as they may be attached to past orders. They are the variations set to Private with zero stock.

== Images ==
- FIX: Products being given photographs belonging to a completely different listing. When a product is created, the plugin looks for a deleted product with the same SKU and takes its images over rather than downloading them again. That match used the SKU alone — but a SKU is often a barcode or a seller reference, and the same one legitimately appears on several listings, so the wrong photographs were adopted. It also marked them as finished, so nothing ever corrected them.
- Images are now only taken over when the photographs are demonstrably the same ones, which keeps this working for relisted items and stops it everywhere else.
- Products already showing the wrong photographs: turn on "Overwrite Images" (Settings -> Import Settings -> Data Mapping) and run an import from eBay. They will be replaced with the correct ones.

== Coins ==
- Coin listings that went to eBay before 3.5.6 are still missing their grading details, Certification, Grade, Year and Circulated/Uncirculated, because at the time the plugin did not recognise their category as a coin category. Fixing that changed what future pushes send; it did nothing for listings already on eBay, and nothing about them looks wrong from inside WooCommerce.
- The plugin now finds those listings for you and offers to send them again, with a count and a single button. It needs no eBay lookups to work out which ones, and the notice disappears by itself once they have been updated.
- Nothing is sent to eBay until you press the button.

== Logs ==
- The activity log now states which clock its timestamps use, with the current time in that zone. The times have always been in your WordPress timezone rather than UTC; if they look wrong, the timezone under Settings -> General is the place to change it.

2026-08-07 - version 3.5.6
== Coins ==
- FIX: Coin listings were only recognised as coins when the category was one of five top-level eBay categories, such as "Coins: US". Nobody lists at the top level — a real coin goes in a sub-category like "Coins & Paper Money > Coins: US > Mint Sets". Those were not recognised, so coin handling quietly did not apply: no grading descriptors, no Certification, Grade or Year, and no Circulated/Uncirculated. The only thing that rescued it was setting Item Type to Coins on each product by hand.
- The plugin already records the full category path when you pick a category, so it now reads that. Any category under "Coins & Paper Money" is treated as coins, whatever its depth. Setting Item Type by hand still works and still takes precedence for custom category IDs typed in directly.
- Card categories are unaffected, and a card category can never be read as a coin one.

== Housekeeping ==
- Removed three unused leftovers in the API and order code. No change in behaviour.

2026-08-07 - version 3.5.5
== Images ==
- FIX: Turning on "Overwrite Images" still did nothing on existing products. 3.5.4 made the setting work, but only for products the plugin had already decided to revisit — and a product is only revisited when its eBay photo addresses change. For the products the setting exists to fix, those addresses had not changed, so they were skipped before the setting was ever consulted. Switching it on now marks every product to be looked at once, so the change actually takes effect.
- After updating, switch "Overwrite Images" on (Settings -> Import Settings -> Data Mapping) and run an import from eBay. Products are corrected in the background over the following minutes, largest catalogues taking longest. No photos are downloaded again — anything already in your Media Library is reused.
- This happens once per change of the setting, not on every sync.

2026-08-06 - version 3.5.4
== Images ==
- FIX: The "Overwrite Images" setting did nothing. It was read and then never acted on, so a product that already had a main image kept it no matter what the eBay listing showed, and eBay photos were only ever added to the gallery behind it. Turning the setting on now makes the eBay photos authoritative: the first becomes the main image and the gallery is rebuilt from the listing.
- This is why a product could sit there showing a photo that is not on its eBay listing, with no way to correct it except by deleting the image by hand. Leave the setting off and your own images are still left alone, exactly as before.
- Images already in your Media Library are never deleted when the setting is on, only unlinked from the product, since they may be your own uploads or in use on other products.

2026-08-06 - version 3.5.3
== Stock ==
- FIX: Two units taken off WooCommerce stock for every one sold on eBay. eBay has already deducted the quantity by the time the plugin hears about a sale, and the sync writes eBay's figure straight into WooCommerce. WooCommerce was then deducting a second unit of its own when the eBay order was imported. Imported eBay orders no longer trigger that second deduction.
- Turning off "Reduce WooCommerce stock on eBay sale?" did not help, because that setting only governed a third path. It is now clear what it does: it applies only to products that are not linked to an eBay listing. Linked products always take their quantity from eBay directly, so nothing is deducted on top.
- Stock now moves by exactly the quantity sold.

== Variable Products ==
- FIX: Variable products duplicated when one sold on eBay. eBay's SKU for a variable listing usually belongs to one of the variations rather than the parent product. The plugin refused to match a SKU held by a variation, so it did not recognise the product it had already imported and created a second one alongside it, with the same attributes and price and a SKU ending in the eBay item number. It now matches the variation's parent product, which was the intent all along.
- FIX: A product's own variation is no longer mistaken for a SKU clash, which was renaming the parent product's SKU on every sync of a variable listing and leaving the listing unmatched next time round.
- Existing duplicates are not removed automatically, since only you can say which copy to keep. The duplicate is the one whose SKU ends in "-" followed by the eBay item number.

== Syncing ==
- FIX: Listings added or changed while the connection was down were never imported, and no later sync went back for them. When a scheduled sync failed — an expired token, a connection problem — it still moved its position forward as though it had succeeded, so the period it never managed to read was stepped over permanently. A failed sync now holds its position and reads that same period again on the next run.
- FIX: The same loss over longer outages. eBay only allows 48 hours of changes to be requested at once, so a site offline for longer catches up in stages — but each stage then jumped the position to the present instead of to the end of the stage it had just read, discarding the very backlog it was working through. It now resumes exactly where it left off.
- If products went missing during an outage, run Fetch Inventory once to bring them in. Nothing will be lost this way again.
- FIX: Scheduled syncs could be skipped without saying so. Each delta sync claimed a lock and never gave it back, so the next run found it and reported "Stale lock detected. Breaking lock". At the default 15 minute interval that was only noise, but on a shorter interval every run after the first was refused and skipped silently, and a manual Fetch Inventory started within ten minutes of a delta sync was refused for the same reason. The lock is now released on every exit, including errors.
- Connection problems are now reported usefully. "Token Refresh Error Body: null" only meant the reply could not be read; the log now records the HTTP status and the start of the actual response, so a failure to reconnect can be diagnosed.

== Settings ==
- FIX: Import Settings and Push to eBay Settings sit side by side again. A field left unclosed in the markup was swallowing the fields below it and pushing the second panel out of the two-column layout.

2026-08-03 - version 3.5.2
== Listings ==
- FIX: GTC listings being shown as Ended while still live on eBay. eBay renews a Good 'Til Cancelled listing roughly every 30 days and moves its end date forward each time, but the plugin treated the end date it had last seen as final. So about a month after a listing was last synced it was marked Ended, and offered a "Relist" button that would have created a second, duplicate listing alongside the one still running. The plugin now confirms with eBay before marking anything ended, and a listing eBay reports as still active is put back to Active.
- Fixed-length listings (1 to 10 days, 30 days) are unaffected and cost no extra API calls: their end date really is final. Only GTC listings, and older items with no recorded duration, are checked with eBay, at most 40 an hour, and each check pushes the next one out to that listing's next renewal.
- An eBay outage can no longer mark listings as ended. A failed check leaves the listing exactly as it was.

== Coins ==
- FIX: "eBay requires these item specifics ... Circulated/Uncirculated" blocking coin listings even after the condition was set. The plugin sent the coin's condition to eBay one way, but never as the Circulated/Uncirculated item specific eBay asks for, so there was no way to satisfy it from the condition selector. It is now filled in automatically from the condition already chosen: Uncirculated for uncirculated coins and for Mint State, Proof and Specimen grades; Circulated for everything else, including "About Uncirculated", which is a circulated grade despite the name.
- Anything you set yourself as a product attribute still wins, so you can always override it.
- Item specific names no longer have to be typed exactly. "Circulated / Uncirculated" and "circulated-uncirculated" are now recognised as the same field, and are corrected to eBay's own spelling before being sent. Previously a near miss passed the plugin's own check and was then rejected by eBay.

== Bulk Tools ==
- NEW: Change listing format in bulk. On the Products list, select any number of products and choose "eBay: set format to Fixed Price / GTC" or "eBay: set format to Auction / 10 days" from the Bulk actions menu. Built for the cycle of running 10-day auctions, moving the unsold ones to a 30-day GTC, and switching back to an auction at a new price later on.
- Setting the format does not contact eBay. Select the same products again and choose "Push to eBay" to apply it. eBay cannot change the format of a live listing, so each one is replaced with a new listing.

== Images ==
- FIX: Products showing only one photo when the eBay listing has several. Until an image had been downloaded, the plugin represented the listing with a single stand-in image — the first photo only — so the rest simply did not exist as far as WooCommerce was concerned. The whole set is now represented straight away: first photo as the main image, the rest as the gallery.
- This is why the problem affected only some products. Anything already downloaded had its full gallery; anything still waiting in the queue showed one photo until its turn came.
- If you use "Disable background image localization" (keep eBay-hosted URLs), nothing is ever downloaded — so every product showed exactly one photo, permanently. Those products now show their full gallery.
- Existing products repair themselves. A background pass restores the full photo set on any product left showing a single image, working through your catalogue a hundred at a time whenever someone is in the WordPress admin. No sync, no re-fetch, and no eBay API usage — every photo address was already stored locally, so this is purely a local repair.
- Products that still have downloads outstanding are simply put back in the queue rather than being given eBay-hosted stand-ins, so a product that already has a proper downloaded image keeps it.
- Note: if you had deliberately reduced a product to a single photo, the full eBay set will be restored to it.
- FIX: Listings whose summary data arrives without any usable picture addresses are now fetched in full from eBay rather than imported with no images.
- Housekeeping: eBay-hosted stand-in images are removed once every photo for that product has downloaded successfully, so they no longer accumulate in the Media Library. They are kept if any download is still pending, so a product never temporarily loses photos.

2026-07-31 - version 3.5.0
== Deleted Products ==
- FIX: Products you delete no longer come back. Deleting a product left no record that you had done so, and because the plugin ignored items in the Trash, the next sync could not tell a deliberately deleted product from one it had never seen — so it created it again. A product in the Trash carrying the same eBay Item ID is now recognised as a deliberate deletion and left alone.
- FIX: Items that have sold or ended are no longer re-imported. The hourly sync asks eBay for everything that changed recently, and a sale counts as a change — so items were reported to the plugin at exactly the moment they sold, and imported as new products. This was the most common way a deleted item reappeared: it sold, you deleted it, and the next sync brought it straight back.
- If a product already exists for a listing that has ended, it is still marked as ended, so ended listings continue to be reflected. Only creating products for them is prevented.
- Deliberately skipped items are no longer counted as errors on the dashboard.

== Notes ==
- Emptying the Trash removes the record of a deletion. If you empty the Trash and the eBay listing is still live, the product will be imported again on the next sync, as a new product. To remove an item for good, end the listing on eBay first.
- Developers: the tcgiant_sync_reimport_deleted_products filter restores the old behaviour if you want deleted products re-created.

2026-07-31 - version 3.4.3
== Connecting to eBay ==
- The window to complete a connection is now 30 minutes rather than 15, so pausing on eBay's consent screen no longer causes an otherwise valid connection to be rejected. This was described in the 3.4.2 notes but did not make it into that build.

2026-07-31 - version 3.4.2
== Connecting to eBay ==
- CRITICAL: Fixed being unable to connect or reconnect your eBay account. Attempting to connect failed with "Invalid callback data or state. Debug -> Code: NO | State: ...". This affected every version from 3.1.3 onwards and could not be worked around — reinstalling the plugin or unlinking on eBay's side made no difference.
- Cause: 3.1.3 added a security check that sent an extra "state" value to the connection service. That service uses the presence of that value to tell an incoming callback from eBay apart from a request to start a new connection, so every connection attempt was misread as a broken callback and rejected. The value is no longer sent.
- The security protection added in 3.1.3 is unaffected. The safeguard is a record kept on your own site that a connection was started from the Settings page, and that check is unchanged — connection details still cannot be planted by following a link from elsewhere.

2026-07-31 - version 3.4.1
== Relisting ==
- FIX: You can now relist an ended listing. Pushing a product whose eBay listing had ended always failed with "You are not allowed to revise ended listings", and there was no way out — the product kept its old Item ID, so every attempt tried to revise the same ended listing again. Ending a listing effectively made the product unlistable. Pushing now creates a fresh listing automatically when eBay reports the old one has ended.
- FIX: You can now change listing type after ending. eBay does not allow a listing's format to be changed, so switching between Auction and Fixed Price requires a new listing. That now happens automatically as part of the same push.
- The decision comes from eBay's own response, not from the status stored here, so a listing that is genuinely still live can never be duplicated by mistake. Any other error is reported as before rather than creating anything.
- The button now reads "Relist on eBay" instead of "Update" when a listing has ended, so it is clear a new listing will be created.
- The previous eBay Item ID is kept on the product for reference, and the product is marked Active again once relisted.

2026-07-31 - version 3.4.0
== New ==
- NEW: "Imported Image Size" setting (Settings -> Import Settings). Choose Original, 1200px, 800px or 600px for images downloaded from eBay. eBay serves every size from the same address, so a smaller choice is requested instead of downloading the full-size file and shrinking it afterwards — saving download time as well as disk space, and reducing every thumbnail WordPress generates from it. Roughly 100-300KB per image at Original against 50-120KB at 800px, so a large catalogue can drop by well over half. 800px is ample for a product page on most themes.
- The setting only affects images downloaded from that point on; images already in your Media Library are left alone. Switching it also never causes images to be re-downloaded unnecessarily, because deduplication still tracks eBay's original address.
- Developers: JPEG quality for imported images can be adjusted with the tcgiant_sync_image_quality filter. It applies only while eBay images are being imported, never to your own uploads.

2026-07-30 - version 3.3.5
== Images ==
- FIX: Turning image downloading back on now actually restarts it. If you had "Disable background image localization" switched on, the background task stopped and was never re-scheduled, so switching the setting back to "download to Media Library" appeared to do nothing — and neither did the Process Queue button, because there was no scheduled task left for it to run. The plugin now notices when there are images waiting but nothing scheduled, and restarts the queue automatically within a minute of visiting the admin.
- This also recovers from any other cause of a lost schedule, such as a site migration or a host clearing scheduled tasks.

2026-07-30 - version 3.3.4
== Images ==
- CRITICAL: Fixed broken images on sites using "Disable background image localization" (the "keep eBay-hosted URLs" option). Images were never displaying at all in this mode. The plugin stored the eBay image address in the WordPress field meant to hold a file path, and WordPress treats that field as a location inside your uploads folder — so it built addresses like "https://yoursite.com/wp-content/uploads/https://i.ebayimg.com/..." which cannot load. Product images, gallery images and thumbnails in the admin product list were all affected. Images now resolve to the correct eBay address.
- Existing products are corrected automatically — no re-import needed. Images should appear immediately after updating.
- Housekeeping: the bad file-path value is cleaned off affected images in the background, so other plugins that read that field (media tools, backups, CDN integrations) are no longer given a web address where they expect a filename.

2026-07-30 - version 3.3.3
== Images ==
- FIX: Products stuck showing an eBay-hosted image now repair themselves. If a download failed at some point, the product kept a temporary stand-in image pointing at eBay — which stops working once that listing ends. The plugin could not tell that stand-in apart from a real downloaded image, so it considered the product finished and never revisited it. Because the eBay image addresses never change, neither a re-sync nor a full re-fetch could rescue it either. Affected products are now detected and re-queued automatically on the next ordinary sync. No action needed.
- FIX: "Re-sync images only" now genuinely re-downloads. It previously skipped any product whose eBay image addresses had not changed, which is exactly the situation you would be using the tool in.

2026-07-30 - version 3.3.2
== Operations Buttons ==
- FIX: "Prune Inventory" was posting the same action as "Fetch Inventory", so it started a full import rather than a prune. It now has its own action, an accurate description, and a confirmation — removing products that are no longer on eBay requires checking every listing first, so it necessarily runs a scan and prunes at the end.

Continuing a page scan and downloading images are WordPress scheduled tasks, not Action Scheduler jobs, so on a site with broken cron — exactly when you would press this button — it did nothing for the two things that actually stall. It now runs both, and reports how many of each it ran.

- FIX: The REST endpoint for starting a sync reported success under the same conditions, and now returns a proper error.

2026-07-30 - version 3.3.1
== Security ==
- Credentials are no longer written to the activity log. When a token refresh failed, the relay's full response was logged verbatim — an unexpected or partial response could put an access token, refresh token or the relay signing key into a plaintext file that ends up in support bundles and backups. Those values are now replaced with [redacted].

== New ==
- NEW: Listings created from WooCommerce now include your product attributes as eBay item specifics. Previously they were sent with almost none, which eBay penalises in search results — and for categories with mandatory aspects, rejects outright.
- NEW: Required item specifics are checked before pushing. If eBay requires an aspect for the chosen category and it is empty, the push stops and names exactly which ones are missing, instead of failing at eBay with a generic error. If eBay's metadata service is unreachable the check is skipped rather than blocking the listing.
- NEW: "Host listing images on eBay?" setting (Settings → Push to eBay). Listings normally reference images on your own site, which requires eBay to be able to reach it — that fails on password-protected sites, sites behind bot protection, and breaks if you ever change domain. Turn this on to upload images to eBay Picture Services instead. Uploads are cached per image, so repeat pushes do not re-upload, and if an upload fails the listing falls back to the site URL rather than failing.

== Background Tasks ==
- FIX: Page scanning no longer stalls between batches. The scanner asked WordPress to run cron immediately, but that request is ignored when the scanner is itself running from cron — which it always is — so each batch waited for the next scheduled tick instead of continuing straight away.
- FIX: Background work now runs on hosts that disable WP-Cron. Sites with WP-Cron switched off and no replacement scheduler never ran image localization at all, leaving products pointing at eBay-hosted images that stop working when the listing ends. Admin activity now keeps the queue moving.
- NEW: "Background Tasks" indicator in System Health showing whether scheduled work is running on time, so a misconfigured host is visible rather than silently doing nothing.

2026-07-30 - version 3.2.0
== Data Safety ==
- CRITICAL: Duplicating a product no longer copies its eBay listing link. WooCommerce copies all custom fields when you duplicate, so the copy inherited the original's eBay Item ID and appeared to already be listed — while actually pointing at the original's live listing. Pressing Update on the copy would have overwritten the original's real eBay listing with the copy's title, price and images, and End Listing would have closed it. Duplicates now start unlinked, as a product that has never been listed. Per-product export settings (category, condition, grader, policies) are still copied, since that is the point of duplicating.
- CRITICAL: Products duplicated BEFORE this fix still carry the stale link. Push and End Listing are now blocked for any product that shares an eBay Item ID with another, an admin notice lists the affected products, and a new "Unlink from eBay" button on the product's eBay Listing tab clears the bad link. Unlinking is local only — it never changes or ends the eBay listing.
- CHANGED: Variations that disappear from an eBay listing are no longer deleted. They are set to private and out of stock instead. A partial or degraded eBay response previously destroyed those variations permanently, along with their links to past order line items. Retiring them is reversible; deleting them was not.
- FIX: eBay order values are parsed properly. Amounts arriving as structured values (which happens whenever eBay includes a currency attribute) were being cast directly to a number, silently producing $1.00 orders with no error. Order totals, shipping costs, line item prices and quantities now all go through the same normalizer the product importer uses.
- FIX: Order import now reads every page. It requested only the first 100 orders of the last 24 hours and ignored the rest, so busy stores silently lost orders.

== Security ==
- SECURITY: The eBay OAuth callback accepted account credentials without verifying who sent them. It ran on admin_init with no nonce and no capability check, so any logged-in user — or a crafted link followed by an administrator — could replace the site's stored eBay tokens and relay signing key with their own, redirecting the store's listings and stock pushes to another eBay account. Connecting now goes through a nonce-protected handler that records a one-time state token, and the callback requires an administrator plus a pending handshake before it will store anything.
- SECURITY: Removed the hardcoded fallback signing key used to verify eBay Marketplace Account Deletion notifications. Because the key shipped inside the plugin, anyone with a copy of the source could forge a valid signature against a site that had not yet been issued a per-site key, and that endpoint erases customer data from orders. Sites without a per-site key now reject notifications instead. If deletion notifications stop being accepted, reconnect your eBay account from Settings to be issued a key.
- SECURITY: Deletion notifications are now rejected if their timestamp is more than 5 minutes old, so a captured request can no longer be replayed indefinitely.

== Critical Fixes ==
- CRITICAL: Importing from eBay could permanently END live eBay listings. Every import writes stock, which WooCommerce reports as a stock change, which the plugin then pushed back to eBay — and any listing that mapped to 0 available stock triggered auto-end. Sold-out-but-active listings were being closed as a side effect of importing them. Stock writes that originate from eBay are now excluded from the WC → eBay push entirely.
- CRITICAL: The same loop also queued one redundant eBay API call per imported product, burning through the daily call budget on large stores. A 10,000-item import no longer generates 10,000 pointless stock pushes.
- CRITICAL: A single failed API request part-way through a scan was treated as "no more pages". The scan finished early and the orphan pruner then trashed every product belonging to the pages that were never reached — on a store failing half way, roughly half the catalogue. Failed requests are now reported as errors and keep their progress, and pruning is blocked unless the scan completed cleanly.
- CRITICAL: Orphan pruning has two further safety nets. It refuses to run when no active eBay Item IDs were recorded, and it aborts if it would retire more than 20% of eBay-linked products in one pass (adjustable via the tcgiant_sync_prune_max_ratio filter).
- CRITICAL: Image migration on relist could strip images off live products. When a product was created it looked for a donor product sharing the same eBay SKU and took its thumbnail and gallery — but did not check the donor was in the trash, so two active listings sharing one seller SKU meant the second import blanked the first product's images. It now only ever harvests from trashed products.
- CRITICAL: Background image localization marked a product "done" even when every download had failed, and the pending queue only ever looks at products not yet marked done. One timeout or temporary eBay CDN error lost that product's images permanently. Failed downloads are now retried up to 3 times with a 10-minute backoff, permanent 404/403 errors are recognised and not retried, and only genuinely completed products are marked done.
- CRITICAL: The weekly inventory reconciliation called a method that does not exist, so it crashed on every run — taking down any other scheduled task queued behind it in the same cron tick. It now uses the correct API call, reads the correct response shape, walks all pages instead of only the first 200 listings, compares available stock rather than listed quantity, and can no longer take down the cron run.
